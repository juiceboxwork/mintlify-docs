The Juicebox Model Context Protocol (MCP) server lets AI models and agents access and interact with your Juicebox data through a standardized interface. Connect it to Claude, ChatGPT, Cursor, or any other MCP-compatible tool to read your recruiting analytics and create or calibrate agents in Juicebox, all without leaving your AI client.

## **Permissions & access**

The Juicebox MCP server requires a paid Juicebox plan. Free-plan orgs can't complete the OAuth flow; the consent screen surfaces a `free_plan_not_eligible` error prompting an upgrade. Any MCP token minted before a downgrade to free stops working immediately.

Within paid plans, analytics and agent tools work on any tier; shortlist tools, `get_project`, `get_sequence_run_emails`, and per-candidate identifying fields in `get_data` require the Business plan. `answer_product_question` is open to any connected user on a paid plan regardless of seat or scope. `get_candidate_details` additionally spends export credits, metered per candidate against your organization's balance.

## **Authentication**

Our MCP server authenticates each user individually via OAuth. Every user completes their own OAuth flow during setup, so the server only returns data that the user can already see in Juicebox. A user cannot query projects, searches, or candidates they do not otherwise have access to in the app.

## **Set up your MCP client**

The Juicebox MCP server is client-agnostic and works with any MCP-compatible tool.

MCP access is gated per organization. MCP is on by default for every organization, so teammates can connect a client as soon as they finish the OAuth flow. If your organization has opted out of MCP, the consent screen shows an `mcp_not_enabled_for_org` error asking you to have an admin turn it back on. Contact your Juicebox representative to toggle MCP access for your organization.

If you invite a new teammate through the connection flow in your MCP client, they'll first go to app.juicebox.ai to finish creating their Juicebox account. They then return to the MCP consent screen to approve access.

The server URL is:

[https://mcp.juicebox.ai/v1](https://mcp.juicebox.ai/v1)

_Note: this URL is only used by MCP clients. Opening it directly in a browser will show an error, which is expected._

Select your client below for setup instructions. During setup, you'll see an approval screen listing the permissions the MCP server requests: reading your recruiting analytics and creating or calibrating agents on your behalf. Click Approve to continue.

Claude, ChatGPT, and Cursor are recognized as first-party clients and skip the unverified-application warning. For any other client, the consent screen shows an "Unverified application" notice reminding you that the app's name is self-reported. Check that the redirect destination shown on the consent screen matches the app you started the connection from before approving.

### **Claude**

1. In Claude, go to **Settings \> Connectors** and search for Juicebox, or go there directly with this link: [<u>claude.ai/directory/connectors</u>](https://claude.ai/directory/connectors/dc1671e0-b14c-47b8-a625-e835ae4067ba)
2. Select **Juicebox** and click **Connect**.
3. You'll be prompted to log in to Juicebox (if you aren't already) and select **Approve** in the MCP access window.

Using the Claude CLI (Claude Code)? Add the server with the following command, then complete the OAuth flow when prompted:

claude mcp add --transport http juicebox [https://mcp.juicebox.ai/v1](https://mcp.juicebox.ai/v1)

### **ChatGPT**

1. In ChatGPT, open **Settings \> Apps** and search for Juicebox, or use this link: [<u>chatgpt.com/apps?q=Juicebox</u>](https://chatgpt.com/apps?show_chat_button=true&q=Juicebox)
2. Select **Juicebox** and click **Connect**.
3. Follow the authorization prompts to complete setup.

### **Cursor and other IDEs**

1. Open **Cursor Settings \> Tools & MCPs \> New MCP server**.
2. Paste the following into your configuration:

\{

  "mcpServers": \{

    "juicebox": \{

      "url": "[https://mcp.juicebox.ai/v1](https://mcp.juicebox.ai/v1)"

    \}

  \}

\}

3. Save and restart Cursor. When you use a Juicebox tool for the first time, complete the OAuth flow to connect your workspace.

### **Gemini CLI**

Juicebox's MCP server supports dynamic client registration, so it can be configured with Gemini CLI:

1. Add the server with the command: gemini mcp add --transport http juicebox [https://mcp.juicebox.ai/v1/](https://mcp.juicebox.ai/v1/)
2. Complete the auth process. For more on Gemini CLI's auth process, check out [<u>their MCP server guide</u>](https://geminicli.com/docs/tools/mcp-server/#automatic-oauth-discovery).
3. Restart the Gemini CLI (or run /mcp reload if the session is active) and check the status using the built-in command /mcp list. You should see the server listed with a "Connected" status.

### **Tools**

**Analytics tools**

- get\_schema — Shows a catalog of what data you can ask about: the available tables, fields, and example questions. You call this first so you know what you're allowed to query.
- get\_data — Runs a read-only report and returns rows of data (e.g. counts, breakdowns, activity). It's the actual "answer my analytics question" tool, always limited to your organization's data. Aggregate metrics (counts, breakdowns) are available on any paid plan; per-candidate identifying fields such as names, titles, companies, locations, and LinkedIn URLs are a Business-plan feature. Starter and Growth callers can still run aggregates over those fields but can't select or filter on them row-by-row. On those plans, `get_schema` hides the gated dimensions and points you at aggregates instead.
- resolve — Turns a human name or link into the internal ID the system needs. You give it a project name, a teammate's name/email, a sequence title, or an agent name (and it hands back the matching ID), so other tools can act on the right thing.

**Shortlist tools**

Shortlist tools are a Business-plan feature and only cover candidates a recruiter has explicitly saved to a project's shortlist — not the full candidate pool, sourced/searched results, or every contact in your organization. Every successful shortlist tool response includes a `disclaimer` field restating this scope so calling agents can't confuse it with a broader search.

- search\_shortlist — Lists candidates saved to a project's shortlist, with optional filters (e.g. by title or school). Returns identity only — contact ID, full name, and LinkedIn URL — for each match. Read-only, and only for projects you're allowed to see. Use `get_candidate_details` to hydrate the rest of a candidate's profile.
- get\_candidate\_details — Hydrates richer details on specific shortlisted candidates that `search_shortlist` doesn't return, including current title and company, location, skills, total years of experience, job tenure, and full experience and education history. This tool consumes export credits: revealing a candidate who has not already been exported this billing period costs one credit and stamps them as exported (re-reads are free). Candidates already exported this period cost nothing. If your organization doesn't have enough credits for every unexported candidate in the batch, the call is rejected without spending any. Preview the cost with `preview_candidate_details_cost` before calling.
- preview\_candidate\_details\_cost — Given a batch of contact IDs, reports how many export credits `get_candidate_details` would consume without revealing anything or spending a credit. Use this to size a batch against your remaining balance.
- get\_export\_credits — Reports your organization's remaining export credits, when the current billing period ends, and when credits next refresh, so you can plan `get_candidate_details` calls against the available budget.<br />

**Project tool**

- get\_project — Gives a summary of one project: its basic info plus how much is in it (number of saved searches and shortlisted candidates).

**Sequence tool**

- get\_sequence\_run\_emails — Reads one sequence run's outreach thread by `sequenceRunId`: outbound step emails plus any candidate replies, in chronological order. Business-plan only, and restricted to sequences you're allowed to see. Two modes: an index mode returns message metadata (subject, from, to, date, status, snippet) with no bodies, and a drill mode returns one message's full plain-text body with cursor-based chunking for long threads. Look up the `sequenceRunId` from `get_data`, which exposes it as a deep-link key on the `sequence_runs` table.

**Knowledge tools**

- answer\_product\_question — Answers general "how does Juicebox work" questions (objects, agents, statuses, capacity, settings, where features live) from Juicebox's canonical product guide. It is read-only and returns no live account data. Available to any connected user on a paid plan regardless of seat or OAuth scope. Use the analytics, project, or shortlist tools for live details on specific projects or candidates.

**Agent (Eren recruiting agent) tools**

- get\_agent\_schema — Explains how recruiting agents work: what you need to create/configure one, the lifecycle (start, pause, resume, close, reopen), and current limits. You read this first before creating an agent.
- create\_agent — Creates a new automated recruiting agent for a role (or fine-tunes an existing one). Requires a job title, location, and years of experience up front; if any are missing, the call returns immediately with the specific fields to collect. When enough is provided, `create_agent` kicks off calibration in the background and returns a `calibrating` status right away so your MCP client doesn't time out on the multi-second setup turn. Poll `check_agent_status` to find out when the agent starts sourcing. If the agent has already started sourcing, `create_agent` refuses to recalibrate and returns `already_sourcing` — finish the change in the Juicebox web app instead.
- check\_agent\_status — Read-only status check for an agent kicked off by `create_agent`. Returns `busy` while calibration is running (keep polling), `sourcing` once the agent has started searching, or `action_required` when the agent is idle and needs input it can't collect over MCP (finish setup in the Juicebox web app). Use it after every `create_agent` call to know when the agent is live. Cap polling at roughly 10 calls per agent; if calibration is still running after that, hand off to the Juicebox web app. A hard limit of about 30 polls per hour per user and agent returns a terminal `poll_limit_reached` result, telling the caller to stop polling and open the agent in the app.
- start\_sourcing — Tells an already-set-up agent to begin actively searching for candidates. Usually not needed since create\_agent starts automatically, but useful for restarting or retrying.
- manage\_agent — Controls an existing agent's lifecycle: pause, resume, close, or reopen it.
